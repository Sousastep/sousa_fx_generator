Density3 — Airwindows (Chris Johnson), MIT
Page: https://www.airwindows.com/density3/

What it is: a sine-based overdrive "dirt shaper" with a gentle highpass in
front of it. Density 0 is clean; positive values drive the signal into a
sine-shaped saturator (PurestSaturation technique), crossfading toward full
saturation by 1 and adding drive beyond that; negative values are an
"inverse saturation" that keeps the tone but dries up the quiet parts — a
soft, gatey thinning. Not a compressor.

Parameters:

- density  (Density)  -1 .. 4, default 0 (clean)
  -1 .. 0 : inverse saturation, strongest at -1. Very level dependent: at -1
            a tuba at normal level comes out roughly 20 dB quieter and
            grainy, so start around -0.3.
   0      : clean.
   0 .. 1 : blend toward sine saturation.
   1 .. 4 : sine saturation with increasing drive (4 = 5x into the sine).
  Shown exactly as the VST displays it; original knob A = (density + 1) / 5.
  The VST's default is -1; this port defaults to 0 so it isn't near-silent
  on first load.

- highpass_hz  (Highpas)  0 .. 4000 Hz, default 0 (off)
  One-pole highpass on the processed (wet) path only, before the
  saturator, so heavy lows don't get saturated; blend them back with
  mix_pct. Exponent taper for fine control at the low end. The original
  knob B set the filter coefficient as B^3 (B = 1 at 44.1 kHz removed the
  whole wet signal); this port sets the -3 dB corner directly.

- output_db  (Output)  -36 .. 0 dB, default 0
  Level of the processed path (applied before the dry/wet mix). Original
  knob C was linear gain 0..1.

- mix_pct  (Dry/Wet)  0 .. 100 %, default 100
  Linear blend of processed and dry signal.

Port notes: DSP matches the original double-precision path (differential
test vs. the airwindows C++, max diff below -150 dB). The random generator
used for the denormal guard runs on native integer operations
(bit-identical, about 65% fewer ns/sample on a translated test harness).
