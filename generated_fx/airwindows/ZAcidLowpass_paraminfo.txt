ZAcidLowpass — Airwindows (Chris Johnson), MIT
Page: https://www.airwindows.com/zacidlowpass/

What it is: "like if an e6400 went insane and grew shark teeth". A failed
(and kept) experiment in cubic-Bezier undersampling: the input is averaged
over cycles set by Cutoff and redrawn as cubic Bezier curves, which acts
like a steep, ringy lowpass crossed with a ring modulator (it jitters
between curve segments). Over/Under split the result into a highpassed and
a lowpassed part like a crossover. Then the Z-filter output stage: drive,
a DC blocker, 15.5 kHz biquad lowpasses around a soft clipper, output
trim.

Parameters:

- cutoff_hz  (Cutoff)  20 .. 10000 Hz, default 620 Hz
  Where the lowpassed part is 3 dB down (measured: about 0.215 x the
  internal Bezier cycle rate). Exponent taper. The original knob A set the
  cycle rate as A^3 (A 0.5 = ~620 Hz at 48 kHz; A 1 = ~4.9 kHz); above
  that, up to 10 kHz, is an extension of the same law.

- over_pct  (Over)  0 .. 100 %, default 0
  Level of the highpassed part (input minus the Bezier lowpass). Over on
  its own = gritty highpass; with Meltdown at 0 it gives the "crazy
  overtones and harsh noise" sound.

- under_pct  (Under)  0 .. 100 %, default 100
  Level of the lowpassed part. Over and Under both at 100 % give back
  roughly the original sound.

- meltdown_pct  (Meltdwn)  0 .. 100 %, default 0
  Feeds the raw input instead of the cycle average into the curve
  points: aliasing and chaos, wilder and dirtier. With Over, it works the
  other way round (0 % is the harsh one).

- drive_db  (Drive)  -24 .. +80 dB, default 0
  Gain into the Z-style soft clipper. Original knob E: gain = (10E)^4, so
  E 0.1 = 0 dB and E 1 = +80 dB — made for abuse. Nominal tuba levels
  start to clip around +10 dB.

- output_db  (Output)  -36 .. 0 dB, default 0
  Output trim (the original knob F was linear 0..1).

Port notes: DSP matches the original double-precision path (differential
test vs. the airwindows C++, max diff below -290 dB with float-exact knob
values; the cycle grid makes it very sensitive to the original's float32
knob rounding). Optimized: the cubic Bezier weights are computed once per
sample for both channels (six pow() calls removed) and the random
generator runs on native integer operations (bit-identical) — about 53%
fewer ns/sample on a translated test harness. The fixed 15.5 kHz filters
need a sample rate of 32 kHz or more.
