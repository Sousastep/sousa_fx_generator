TakeCare — Airwindows (Chris Johnson), MIT
Page: https://www.airwindows.com/takecare/

What it is: a vibrato-modulated delay-network "space" — a 3x3 matrix of
delay lines per side (18 lines of up to 32767 cells, ~4.7 MB) whose taps
are swept by nine phase-offset copies of one vibrato LFO, cross-fed
through a mixing matrix with regeneration, soft-clipped and run at a
reduced internal sample rate ("derez") with Bezier smoothing. Anything
from chorused ambience to warbly, seasick tape-space and runaway
self-oscillating drones.

Parameters:

- speed_hz  (Speed)  0.01 .. 400 Hz, default 0.03 Hz
  Vibrato rate. Slow = drifting tape wobble; tens of Hz = growly
  chorus/ring textures; hundreds of Hz = FM-like grit. Steep taper (the
  original was A^5). With rando_pct up, the real rate wanders around
  this value (up to ~1.3x on average).

- rando_pct  (Rando)  0 .. 100 %, default 12.5
  How much each LFO cycle's speed is randomized. 0 = steady vibrato.
  Original knob B: B^3 = rando_pct/100 (B 0.5 = 12.5 %).

- depth_pct  (Depth)  0 .. 100 %, default 25
  How far the taps sweep, as a share of the buffer length. 0 = static
  delays (metallic, combed), high = deep pitch smear. Original knob C:
  C^2 = depth_pct/100.

- regen_pct  (Regen)  0 .. 100 %, default 50
  Feedback through the network. Above roughly 80 % it builds into
  self-sustaining, much louder drones (a soft clipper keeps it bounded,
  but it can end up 20 dB above the input) — ride output_db.

- derez_pct  (Derez)  -100 .. +100 %, default 0
  Internal sample-rate reduction. Distance from 0 = how much lower the
  rate is; negative = stepped (held samples, gritty), positive = smooth
  (Bezier-interpolated, darker). Around 0 it already runs near half the
  host rate, as the original does. Original knob E = 0.5 + pct/200.

- buffer_ms  (Buffer)  5 .. 680 ms, default 175 ms
  Base delay length (room size). Changes glide: the buffer moves one cell
  per internal sample toward the new length, which bends pitch on the
  way. The longest settings are limited by the 32767-cell lines (680 ms
  at the highest internal rate; more is available at heavier derez, up
  to the slider's maximum).

- output_db  (Output)  -36 .. +6 dB, default 0
  Level of the processed signal (before the dry/wet mix). The original
  knob G was linear gain 0..1; +6 dB is an extension.

- mix_pct  (Dry/Wet)  0 .. 100 %, default 100
  Linear wet share (the original knob H used wet = 1-(1-H)^2).

Behaviour change vs. the VST: speed and buffer are given in Hz and ms and
converted through the current derez cycle rate, so they stay put when you
move Derez or the sample rate. In the VST both were counted in derez
cycles, so lowering the rate also slowed the vibrato and lengthened the
delays (tape-speed style).

Port notes: fixed a real port bug — `bezFraction/(bezFraction+1.0)`
compiled to an integer division (0), which broke the Bezier timing and
put the old port up to -47 dB away from the original (see
docs/rnbo_codebox/example28.md). With that fix the core is bit-identical
to the airwindows C++. Optimized: the nine vibrato sines come from one
sin/cos pair (angle addition; max diff -220 dB) and the random generator
runs on native integer operations (bit-identical) — about 33% fewer
ns/sample on a translated test harness, measured old port vs new.
