ToTape9 — Airwindows (Chris Johnson), MIT
Page: https://www.airwindows.com/totape9/

What it is: the most intense Airwindows tape machine. In order: input
gain; "Dubly" (a Dolby-like encode that compresses and lifts the highs,
undone after the tape stage — Tilt and Shape set how it is calibrated);
flutter (a randomly wandering pitch wobble from a short modulated delay);
bias (under-bias makes the tape "stick" and soak up highs, over-bias
slew-limits through a golden-ratio chain of stages); hysteresis; the
TapeHack2 saturation core with slew-dependent darkening; a resonant head
bump; and the new ClipOnly-style output clip that adds a faint noise edge
only while it is clipping.

Parameters:

- input_db  (Input)  -24 .. +12 dB, default 0
  Drive into the tape. Original knob A: gain = (2A)^2 (0.5 = unity,
  1.0 = +12 dB). Push it to slam the tape core.

- tilt_pct  (Tilt)  -100 .. +100 %, default 0
  Leans the Dubly calibration toward brightness (+) or darkness (-), like
  mis-calibrating noise reduction on purpose. Original knob B =
  0.5 + pct/200.

- shape_pct  (Shape)  -100 .. +100 %, default 0
  Moves the Dubly filter corners: negative = old-school, sonorous;
  positive = big-studio, cleaner highs. Original knob C = 0.5 + pct/200.

- flutter_ms  (Flutter)  0 .. 10 ms, default 0.0177 ms
  Flutter depth: the delay swing of the wobble (twice this value
  peak-to-peak). Below ~0.1 ms it is realism; several ms is a chewed
  cassette. Original knob D gave D^6 * 50 samples at 44.1 kHz (max about
  1.13 ms); this port allows up to 10 ms, the original's internal buffer
  limit (498 samples).

- flutter_hz  (FlutSpd)  0.01 .. 140 Hz, default 17.6 Hz
  Flutter speed. The actual rate keeps wandering between about 25 and
  100 % of this value (the original's random walk), so the default
  flutters at roughly 4-17 Hz. Original knob E: 0.02*E^3 rad/sample at
  44.1 kHz.

- bias_pct  (Bias)  -100 .. +100 %, default 0 (calibrated)
  Negative = under-bias: the signal sticks near its previous values,
  duller and grainier. Positive = over-bias: progressively stronger
  slew limiting (rounder, softer highs). 0 bypasses the bias stage.
  Original knob F = 0.5 + pct/200.

- head_bump_pct  (HeadBmp)  0 .. 100 %, default 50
  Amount of the resonant low-frequency head bump (drive and mix together).
  Original knob G = pct/100.

- head_freq_hz  (HeadFrq)  25 .. 200 Hz, default 68.75 Hz
  Centre of the head bump (two bandpasses, the second at 0.9375x). Set it
  under the tuba's fundamental for weight, on it for boom. Same Hz as the
  original displays (knob H: H^2*175 + 25).

- output_db  (Output)  -24 .. +6 dB, default 0
  Level into the final clip stage. 0 dB (original knob I 0.5) just
  touches it; higher values hit the clipper harder for "beyond tape"
  loudness; lower values leave only the tape sound.

Note: 9 controls — one more than this repo's usual limit of 8; all of
the original's controls are kept.

Port notes: DSP matches the original double-precision path (differential
test vs. the airwindows C++; max diff below -135 dB with float-exact knob
values — flutter is chaotic, so the original's float32 knob rounding
alone can move it audibly). The random generator runs on native integer
operations (bit-identical), about 10% fewer ns/sample on a translated
test harness.
