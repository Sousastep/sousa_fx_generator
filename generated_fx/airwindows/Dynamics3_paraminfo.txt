Dynamics3 — Airwindows (Chris Johnson), MIT
Page: https://www.airwindows.com/dynamics3/

What it is: a Bezier-curve compressor that morphs into an expander. The
gain control is a peak hold (with a linear release) averaged over windows
of "attack" length and joined by a quadratic Bezier curve, so it moves
smoothly without a classic attack/release envelope. It is vari-mu style:
compressing also changes the dry/wet blend (the ratio), not just the gain.
There is no make-up gain — compression makes it quieter. A sine-shaped
soft clip catches what gets through.

Parameters:

- thresh_db  (Thresh)  -4.18 .. +12.54 dB, default +12.54 (= bypass)
  How readily it acts; gain reduction grows with level relative to this.
  The top of the range bypasses the plugin completely (as the original's
  1.0 does). The range is the original's whole span (knob A: threshold =
  (A + 0.618)^2 * 1.618), so even at -4.18 dB it is gentle on a quiet
  tuba: on a peak-normalised tuba take it lowers the level about 5 dB.

- attack_ms  (Attack)  1.5 .. 450 ms, default 12 ms
  Length of each Bezier averaging window: shorter = grabs faster and
  follows the waveform more closely (grittier), longer = smoother, slower.
  Original knob B set it via ((1-B)*0.4)^4 per sample (B 0.382 = 12 ms;
  it stopped getting longer above B 0.75, ~400 ms).

- release_ms  (Release)  1.5 .. 4500 ms, default 80 ms
  How long the peak hold takes to fall from full scale back to nothing.
  Faster release also tames the expansion boost in the inv range.
  Original knob C: ((1-C)*0.4)^4 per sample (C 0.618 = 80 ms).

- inv_wet_pct  (Inv/Wet)  -100 .. +100 %, default +100
  +100 = full compression, 0 = dry, -100 = full "inverse": an expander that
  suppresses the start of each note and lets it flare up afterwards (the
  complement of the compressed sound, not a phase-inverted mix). Strong
  settings can distort, by design. Original knob D = (pct + 100) / 200.

Port notes: fixed a real port bug — `stepped/(stepped+1.0)` compiled to an
integer division (0), which made every Bezier cycle one sample long and
put the old port up to -27 dB away from the original (see
docs/rnbo_codebox/example28.md). Now matches the airwindows C++ in a
differential test (max diff below -135 dB). Attack/release are set in ms
directly, so the original's slightly odd sample-rate scaling is replaced
by exact times. The random generator runs on native integer operations
(bit-identical; about 65% fewer ns/sample on a translated test harness).
