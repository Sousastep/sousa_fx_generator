PurestSquish — Airwindows (Chris Johnson), MIT
Page: https://www.airwindows.com/purestsquish-vst/

What it is: an open-sounding, not-at-all-normal compressor. Several
mu-style gain cells run interleaved on 2- and 3-sample cycles and are
averaged; there are no attack/release controls (release speeds up and
slows down with the signal itself). Make-up gain is automatic and grows as
the threshold drops, so it gets LOUDER as it squishes. It clamps hard on
transients and can do odd things when a sound starts or stops abruptly
(the author's own warning). Bass bloom keeps lows from triggering it.

Parameters:

- thresh_db  (Squish)  -40 .. 0 dBFS, default 0
  Input level above which the gain cells clamp down. Lower = more squish
  and more automatic make-up gain. At 0 dBFS the plugin does almost
  nothing but is about 6 dB quieter than its input (the original's
  make-up split, kept as is). Pushed hard it can drive peaks over
  0 dBFS — trim with output_db. Original knob A sets an internal threshold
  t = 1.01 - (1 - (1 - A/2)^4) that the detector sees after an internal
  boost; this port solves for the input level that actually matters
  (A 0.36 = -12 dBFS, A 0.65 = -24 dBFS, A 1 = -41.6 dBFS).

- bloom_hz  (BassBlm)  0 .. 2000 Hz, default 0 (off)
  Highpass on the detector only (sidechain filter): below this frequency
  notes pass through less compressed, so bass and subs "bloom" while the
  rest is held. Exponent taper for fine control at the low end. Original
  knob B set the filter coefficient as B^4 (B 0.3 ~ 57 Hz, B 0.5 ~ 450 Hz;
  B 1 at 44.1 kHz switched compression off entirely).

- output_db  (Output)  -24 .. +6 dB, default 0
  Output level. The original knob C only attenuated (linear 0..1); this
  port allows +6 dB so the -6 dB at gentle settings can be made up.

- mix_pct  (Dry/Wet)  0 .. 100 %, default 100
  Linear blend with the dry signal.

Source quirk kept: in the alternate-sample cells the original squares
cell E's coefficient where cell D's would be expected; it is part of the
plugin's sound, so the port does the same.

Port notes: DSP matches the original double-precision path (differential
test vs. the airwindows C++, max diff below -145 dB). Optimized:
pow(x,2) -> x*x and the random generator on native integer operations
(bit-identical), about 45% fewer ns/sample on a translated test harness.
